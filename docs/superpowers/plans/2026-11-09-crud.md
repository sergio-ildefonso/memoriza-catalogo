# CRUD do catálogo — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CRUD de produtos numa UI, com escrita real em `products.json` por um servidor Node local.

**Architecture:** Lógica de dados isolada em `server/productsApi.js` (funções sobre caminho de ficheiro, testáveis com `node:test`). `vite.config.js` monta essa lógica como middleware `/api/products` no dev server. Frontend vanilla consome a API e cai para só-leitura quando ela não existe.

**Tech Stack:** Vite 8, Node `node:fs/promises`, `node:test`, HTML/JS vanilla.

**Spec:** `docs/superpowers/specs/2026-11-09-crud-design.md`

## Global Constraints

- Zero dependências novas.
- Formato de `Product` inalterado: `id`, `name`, `description`, `material`, `tipo`, `tamanho`, `image`.
- Escrita atómica (temp file + `rename`) e serializada.
- `image` obrigatório, começa por `images/`, sem `..`.
- CRUD só em dev server; `vite build` continua estático.
- Repo não é git: sem passos de commit.

## Review Focus

- Ficheiro `products.json` ilegível ou inexistente: API devolve 500 e não apaga nada.
- Dois pedidos de escrita seguidos: nenhuma alteração perdida (fila).
- `image` com `../` ou `http://`: rejeitado com 400, ficheiro intacto.
- Página aberta por `file://` ou build estático (sem API): mostra catálogo, sem botões de escrita.
- Apagar o último produto: ficheiro fica `[]`, UI mostra estado vazio e permite criar.

### Task 2: Middleware Vite

**Files:**
- Create: `vite.config.js`

**Interfaces:**
- Consumes: `createProductsApi` da Task 1.
- Produces: rotas `GET/POST /api/products`, `PUT/DELETE /api/products/:id`; JSON, `Content-Type: application/json`.

- [ ] **Step 1: Escrever `vite.config.js`**

Plugin `configureServer` que trata `/api/products` e `/api/products/:id`, lê o corpo JSON (limite ~1 MB), mapeia `err.status` para a resposta, `204` no DELETE, e chama `next()` para rotas não-API. `filePath`: `new URL('./products.json', import.meta.url)`.

- [ ] **Step 2: Verificar com o dev server**

Run: `npm run dev -- --port 5178` (background) e:
`curl -s localhost:5178/api/products | head -c 100` → JSON com 6 produtos.
`curl -s -X POST localhost:5178/api/products -H 'Content-Type: application/json' -d '{"name":"Teste","description":"d","image":"images/placa-nogueira.svg"}'` → 201 com `id:7`; confirmar em `products.json`; depois `DELETE /api/products/7` → 204 e remoção do ficheiro.
